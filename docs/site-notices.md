# FAQの入口・日付付きのお知らせ

公開予定の実データは `data/site-notices.json` に登録します。休診や点検の日付は確認してから登録し、仮の日程は公開しません。患者情報や非公開予定は入れないでください。

1件の形（下記は説明用。実際のお知らせには登録していません）：

```json
{
  "id": "elevator-check-example",
  "enabled": true,
  "publishedOn": "2026-10-01",
  "startsOn": "2026-10-20",
  "endsOn": "2026-10-20",
  "title": "エレベーター点検のお知らせ",
  "message": "【例】9〜12時はエレベーターが利用できません。階段の利用が難しい方は、ご予約の前にご相談ください。"
}
```

- `publishedOn`：掲載を開始する日。
- `startsOn`／`endsOn`：対象日の始めと終わり。同じ日の予定は同じ日付。
- 時刻や注意点は `message` に記載。点検中に休診するかどうかは実運用に合わせ、勝手に断定しない。
- `enabled: false` は非掲載。掲載日前の予定は表示しない。
- トップ・アクセスの小さな案内は、掲載日から対象終了日まで最大3件。画面に重なる固定表示はしない。
- お知らせページでは、掲載日を過ぎた予定を終了後も履歴として残す。日本時間で判定する。
- 日付の切り替わりと、タブへ戻った際に表示を更新。外部APIの読み込みや定期通信は行わない。
- まだ予定がない場合、トップ・アクセスの案内は表示しない。お知らせページには未掲載の説明を表示する。

登録後は `npm run build:site-updates`、`npm test` を実行し、差分とスマートフォン表示を確認してから公開します。このビルドはFAQの共通メニュー・古いリンクの修正も維持します。生成されるブログやサイトマップは変更しません。

FAQ本文・料金・患者様のお声は変更対象に含めていません。旧 `#seo-guide` 等は互換アンカーを残し、以前のブログ等からも現在の説明へ移動できます。
