# 症状別ページ・コラム 読みやすさ改修プロンプト

## 呼び出し方

ユーザーが `1記事プッシュ` と送った場合、この指示書に従って、症状別ページまたはコラムを1件だけ改修し、確認、コミット、プッシュまで行う。

`2記事プッシュ`、`3記事プッシュ` の場合は、指定数だけ同じ工程を繰り返す。各記事の内容や内部リンクが混ざらないよう、1件ずつ確認する。

## 目的

整体院ひざこぞうの症状別ページとコラムを、スマホで長文を読む方にも負担が少ない構成へ整える。

SEOのために情報を増やすことより、重複をなくし、必要な情報へ迷わずたどり着けることを優先する。TOPページは対象外とする。

## 適用範囲と判断基準

- 文字数、見出し数、余白、列数は初期案の目安。数を満たすために内容を増減せず、今回の指定と対象ページの読みやすさで決める。
- 既に採用された画像や構成を、別の箇所の改修に合わせて作り直さない。変更範囲が指定された場合はその範囲を優先する。
- 提案だけの依頼では提案まで。実装依頼では表示確認と今回生じた不具合の修正まで進める。公開範囲と生成手順は [AGENTS.md](../AGENTS.md) に従う。

## 対象の選び方

1. ユーザーがページ名を指定した場合は、そのページを対象にする。
2. 指定がない場合は、未改修で、見出し・カード・重複説明が多い症状別ページを優先する。
3. 次に、古い構成や読みにくい表現が残るコラムを選ぶ。
4. 直近で改修済みのページは重ねて選ばない。
5. 公開日だけを更新する目的の変更は行わない。

## 作業前の確認

- `git status` で既存の変更を確認する。
- ユーザーの未完了変更や、別の記事の変更を混ぜない。
- 対象ページのタイトル、H1、H2、CTA、画像、内部リンク、構造化データを確認する。
- 症状別ページでは、同じ意味の見出しや説明が複数回出ていないか調べる。
- 共通CSSやJavaScriptを変更する場合は、影響するページを確認してから進める。

## 症状別ページの構成

ページ本文は、おおむね次の流れに整理する。症状に合わない項目を無理に残さない。

1. ファーストビュー
2. よくある生活上の悩み
3. 症状についての基本情報
4. 医療機関への相談を優先したい状態
5. 痛む場所だけで判断しない理由
6. 当院で確認することと施術方針
7. 自宅で確認できること・注意点
8. 実際のお客様の声（該当する事実がある場合のみ）
9. 施術の流れ・よくある質問
10. 関連ページ・料金・予約案内
11. 院長メッセージ

本文の主要H2は8〜12個を目安とする。同じ意味の「当院の特徴」「注意したいこと」「自宅でできること」「受診の目安」が複数ある場合は、一つにまとめる。

既存の初回料金と施術の流れは共通部分を使用し、同じ説明を本文中に作り直さない。料金は初回料金のみを表示し、通常施術料金や回数券料金は追加しない。

## コラムの構成

- 本文は1,500〜3,000文字を基本とする。
- H2は4〜7個程度に絞る。
- 冒頭の2〜3文で、誰のどんな疑問に答える記事かを示す。
- 1段落では一つの内容だけを扱い、スマホで3〜5行程度を目安に改行する。
- 医学的な説明、生活場面、受診の目安、まとめを自然につなげる。
- FAQは検索意図に合う質問がある場合だけ3〜5問掲載する。
- 本文途中の予約CTAは最大1回。記事末尾のCTAと役割を重ねない。
- コラムは必ず `content/source/*.md` を編集し、生成ファイルを直接編集しない。

## デザインルール

### 基本

- 普通の本文は白い背景に置き、カードで囲まない。
- 見出し、余白、細い区切り線で文章のまとまりを示す。
- カードや色付きの囲みは、医療機関への相談目安、お客様の声、選択肢、最後の予約案内など、独立させる意味がある情報だけに使う。
- カードの中にカードを入れない。
- 同じページで枠線、角丸、影、バッジを繰り返さない。
- 重要でない要素にアイコンを付けない。

### スマホ

- 横の余白は20px前後を基本とする。
- 本文は16〜17px、行間は1.8〜1.95を目安にする。
- H2の前は48〜64px程度空け、セクションの切り替わりを分かりやすくする。
- 2列・3列のカードをそのまま縦積みにしない。番号付きの行や、区切り線のある一覧へ変える。
- 目次は初期状態を閉じる。
- 固定CTAが本文や電話ボタンに重ならないよう確認する。

### PC

- 長文の一列あたりの読み幅は680〜720px程度を出発点にする。ページ全体の最大幅を固定する規則ではない。横幅を活用する指定があれば、写真と文章の横並びなどで広く使い、スマホ表示を維持する。
- 目次を横に置く場合は、本文を狭くしすぎない。
- 横幅を埋めるためだけにカードを増やさない。
- 5項目など奇数の一覧は、不自然な空白セルを作らず、縦一覧または横罫線の一覧にする。

## 文章ルール

- AIらしい定型文を避ける。
- 「一緒に整理します」「身体づくりを支えます」を各所で繰り返さない。
- 「このように」「さらに」「一方で」「重要です」などの接続表現を必要以上に使わない。
- 読点を増やしすぎず、長い文は二つに分ける。
- 同じ語尾を3回以上続けない。
- 見出しだけを読んでも内容の順番が分かるようにする。
- 300文字未満の短い内容を、さらにH3で細分化しない。
- 川上卓哉本人が話している箇所は、経歴や感動的な物語を創作しない。

## 医療・信頼性ルール

- 「治療」「治る」「完治」「必ず改善」「根本解決」「再発しない」など、結果を保証する表現を使わない。
- 病院、薬、注射、手術、他院を否定しない。
- 医師の指示なく薬を中止するよう勧めない。
- 病名や原因を整体院で断定しない。
- 医療機関への相談を優先すべき症状を残す。
- 実在しないお客様の声、改善率、症例、平均通院回数を作らない。
- 施術歴15年、累計施術約2万件とし、施術結果へ言い換えない。
- 施術者プロフィールは `https://hizakozou.jp/staff.html` へリンクする。
- 着替えの有無は確認できるまで記載しない。

## SEO・AIOルール

- title、description、H1の役割を分ける。
- 地域名と症状名を自然に使い、同じキーワードを繰り返さない。
- 結論や受診目安をページ前半に置く。
- 見出しを質問、判断、行動の単位で分かりやすくする。
- 医学情報は公的機関、医学会、医療機関などの一次情報を確認する。
- 出典、著者・監修者、確認日を残す。
- 関連する症状ページやコラムへ2〜5本程度の内部リンクを置く。
- 関係の薄い記事へ無理にリンクしない。
- URL変更は原則行わない。変更が必要な場合は、リダイレクトとcanonicalを確認する。

## 画像ルール

- 内容に合う既存画像を実際に見て選ぶ。実際の院内・施術者を示す箇所は実写真を使い、古い部屋の写真を差し替える場合は新しい写真の内容も照合する。
- コラムはアイキャッチ1枚、本文画像1〜3枚を目安とする。
- 同じ画像を短い間隔で繰り返さない。
- 画像の直前または直後に、何を見る画像か分かる説明を入れる。
- altは画像の内容を簡潔に説明し、キーワードを詰め込まない。
- スマホで画像内文字が読めない場合は、HTMLで要点を補足するか画像を簡素化する。1枚の説明画像を指定された場合はその意図を保ち、見出し・説明画像・注意書きの関係と必要な拡大表示を確認する。

## 確認と公開

1. 症状名と関係のないテンプレート文が残っていないか検索する。
2. 重複見出し、重複CTA、誤った画像、リンク切れを確認する。
3. 390px前後のスマホ、タブレット、PCで表示を確認する。
4. 横スクロール、画像の切れ、ボタンの重なり、長すぎるカード列がないか確認する。
5. コラムの場合はブログ生成コマンドを実行し、一覧、記事、SEO、MEO、サイトマップ、関連記事を更新する。
6. 必要な検証を実行する。
7. コミット前に変更範囲を確認し、対象外の変更を含めない。
8. 対象記事名が分かるコミットメッセージでコミットする。
9. 現在のブランチをプッシュする。

## 完了報告

次の内容だけを簡潔に報告する。

- 改修したページ名とURL
- 主な変更点
- 確認結果
- コミットID
- プッシュ先
- 次に改修する候補
