# 整体院ひざこぞう コラム改修・継続運用仕様書

- 文書版：1.0
- 作成日：2026年7月18日
- 対象サイト：<https://hizakozou.jp>
- 対象範囲：コラム一覧、コラム詳細、記事生成機能、既存44記事、新規記事
- 最終確認者：川上卓哉

## 1. 目的

整体院ひざこぞうのコラムを、検索順位を上げるためだけの記事群にしない。

足腰の痛みやしびれに悩む人が、知りたいことを落ち着いて読める場所にする。

そのうえで、検索から継続的に読まれる状態を目指す。

具体的には次を実現する。

- 週3回を基本に、無理なく更新を続ける
- 1記事1テーマで、検索した人の疑問に答える
- スマートフォンで長文を読みやすくする
- PCでは本文に集中できる読み幅と目次を用意する
- 記事内に写真や図を配置する
- 関連する症状ページとコラムを自然につなぐ
- 川上卓哉の経験と考え方を、事実の範囲で伝える
- 医療機関を否定せず、整体院で対応できる範囲を明確にする
- AIが作ったように見える文章を減らす
- Search ConsoleとGA4で成果を確認する

## 2. 基本方針

### 2.1 公開本数

最初の2か月は週3回とする。

| 曜日 | 内容 |
|---|---|
| 月曜日 | 新規記事 |
| 水曜日 | 既存記事の本格改修 |
| 金曜日 | 新規記事 |

品質確認まで安定した場合は、週4～5回へ増やしてよい。

週5回の場合も、5本すべてを新規記事にはしない。

- 新規記事：週3本まで
- 既存記事の改修：週1本
- FAQ、図、内部リンクなどの追加：週1本

内容を変えずに日付だけ更新する運用は禁止する。

### 2.2 文字量

本文は1,500～3,000文字を目安とする。

文字数は見出し、画像説明、参考情報を除いたおおよその本文量とする。

1,500文字に満たなくても、疑問への回答が十分なら水増ししない。

3,000文字を超える場合は、次を検討する。

- 重複表現を削る
- 別の検索意図を含んでいないか確認する
- 2記事に分ける
- 詳細部分を関連記事へ移す

Googleが特定の文字数を推奨しているとは扱わない。

### 2.3 公開承認

記事は自動公開しない。

必ず下書きを作成し、川上卓哉が内容を確認してから公開する。

確認対象は次のとおり。

- 医学情報
- 医療機関への受診案内
- 整体院で対応できる範囲
- 施術内容
- 料金、営業時間、アクセス
- 川上卓哉の発言として書かれた部分
- 写真、人物、口コミの掲載許可

## 4. 想定読者

主な読者は、柏市や柏駅周辺に住む40代から70代の人とする。

特に、足腰の痛みやしびれで外出に不安がある人を想定する。

スマートフォンで読む人を第一に設計する。

読者には次のような状況がある。

- 症状について初めて調べている
- 医療機関で説明を受けたが、生活上の疑問が残っている
- 薬、注射、手術について不安がある
- 整体院で何をするのか分からない
- 長い文章を読むことに慣れていない
- 痛みやしびれで集中が続きにくい
- 自分で取り組めることも知りたい

## 5. 川上卓哉の「声」の扱い

### 5.1 記事の語り方

本文は落ち着いた第三者視点を基本とする。

川上卓哉の考えを入れる箇所だけ、一人称を使用してよい。

一人称部分の見出し例は「施術の現場から」とする。

実際に確認していない発言を、川上卓哉が話したように作らない。

### 5.2 川上さんメモ

記事作成前に、可能な範囲で次の情報を用意する。

- 来院者からよく聞く困りごと
- よく確認する姿勢や動作
- 誤解されやすいこと
- 自宅で気をつけてほしいこと
- そのテーマで川上卓哉が伝えたいこと

今回確認されたメモは次のとおり。

- 自分の話を十分に聞いてもらえなかったと感じている人がいる
- 整形外科で湿布や電気などを受け、最終的に手術を提案された人もいる
- 悩みを話しやすい雰囲気を大切にしている
- 分からないことを聞きやすい対応を心がけている
- 身体の状態と進め方を細かく説明する

### 5.3 医療機関との対立を作らない

上記のメモは、医療機関への批判として使用しない。

次のように読者の体験や気持ちとして整理する。

> 医療機関で検査や説明を受けたものの、日常生活の困りごとをうまく相談できなかったと感じる方もいます。

次の表現は禁止する。

- 整形外科は話を聞いてくれない
- 病院では湿布と電気しか行わない
- 病院では良くならない
- 手術は受けない方がよい
- 薬は身体に悪い
- 医療機関より当院が優れている

医師から薬や手術の説明を受けている場合は、自己判断で中止や変更をしないよう案内する。

## 6. Google口コミの利用方針

2026年7月18日に整体院ひざこぞうのGoogleビジネスプロフィールを確認した。

公開口コミでは、次の内容が複数見られた。

- カウンセリングが丁寧だった
- 身体の状態や施術の進め方を細かく説明してもらえた
- 不安や悩みを相談しやすかった
- 状態を確認しながら進めてもらえた
- 運動や自宅での取り組みも教えてもらえた
- 腰、膝、しびれ、歩行など複数の悩みを相談していた

これらは、整体院の姿勢を確認するための材料として使う。

口コミの結果表現を、施術効果の保証には使わない。

口コミを記事へ掲載する場合は、次を守る。

- 投稿者名を必要以上に掲載しない
- 原文を長く転載しない
- 内容を変えて引用しない
- 症状名や経過を勝手に追加しない
- 掲載時点を記載する
- 個人の感想であることを明記する
- Google口コミへのリンクを設置する
- 劇的な表現だけを切り取らない

Google口コミ確認先：<https://www.google.com/maps/search/?api=1&query=%E6%95%B4%E4%BD%93%E9%99%A2%E3%81%B2%E3%81%96%E3%81%93%E3%81%9E%E3%81%86>

## 7. 記事企画

### 7.1 1記事1検索意図

一つの記事で、中心となる疑問は一つに絞る。

例：

- 坐骨神経痛で長く座るとつらい
- 階段の下りで膝が痛い
- 脊柱管狭窄症で休むとまた歩ける
- 朝の起き上がりで腰がつらい

「坐骨神経痛の原因、ストレッチ、病院、手術、整体、料金」を一つの記事へ詰め込まない。

### 7.2 テーマ構成

今後の企画は次の割合を目安にする。

| 種類 | 目安 |
|---|---:|
| 検索されている疑問への回答 | 40％ |
| 日常生活や動作の困りごと | 25％ |
| 医療機関への受診目安 | 20％ |
| 院内での確認、運動、セルフケア | 15％ |

### 7.3 症状クラスター

記事は次のまとまりで管理する。

1. 膝の痛み、変形性膝関節症
2. 腰痛、坐骨神経痛
3. 脊柱管狭窄症、椎間板ヘルニア
4. 股関節、足首、歩行
5. 首、肩、手のしびれ
6. 医療機関への受診目安
7. 運動療法、セルフケア
8. 柏市、柏駅周辺の来院情報

膝関連の記事が多いため、当面は腰、坐骨神経痛、脊柱管狭窄症、股関節、歩行を優先する。

### 7.4 類似記事の確認

新規記事を作る前に、既存記事のタイトル、URL、検索意図を確認する。

似た内容がある場合は、新規作成より既存記事の改修を優先する。

同じキーワードを狙った記事を複数作らない。

## 8. 記事構成

### 8.1 基本構成

記事は次の順番を基本とする。

1. パンくず
2. カテゴリー
3. H1
4. 公開日、更新日、著者・監修者
5. 導入文
6. メイン画像
7. この記事で分かること
8. 本文
9. 医療機関への相談を優先する状態
10. 自宅で試す場合の注意
11. 整体院で確認できる範囲
12. まとめ
13. 関連記事
14. 著者・監修者情報
15. 参考情報
16. 初回案内

記事の内容によって不要な項目は省略してよい。

見出し数をそろえるためだけに項目を追加しない。

### 8.2 文字量の配分

| 部分 | 目安 |
|---|---:|
| 導入文 | 150～250文字 |
| 要点 | 100～180文字 |
| 基本説明 | 300～500文字 |
| 日常生活・動作 | 300～600文字 |
| 受診目安 | 200～350文字 |
| セルフケア・注意 | 250～500文字 |
| 整体院で確認すること | 250～500文字 |
| まとめ | 120～220文字 |

### 8.3 導入文

導入文は、検索した人が困っている場面から始める。

避ける書き出し：

- ここでは○○について解説します
- 近年、○○が注目されています
- ○○で悩んでいる方は多いのではないでしょうか
- ○○は非常に重要です

使用例：

> 買い物へ出かけても、途中でお尻から足がつらくなり、座れる場所を探してしまう。坐骨神経痛と呼ばれる症状には、このような悩みがあります。

読者の不安を決めつけない。

「このまま歩けなくなる」などの恐怖を、予約誘導のために使用しない。

## 9. 日本語表現と改行

### 9.1 文の長さ

- 一文は40～70文字を目安にする
- 80文字を超えた場合は分割を検討する
- 一文の読点が3つ以上なら見直す
- 主語と述語が離れすぎないようにする
- 二つ以上の話題を一文へ詰め込まない

数値は機械的な制限ではない。

声に出して読んだとき、息継ぎしにくい文を分ける。

### 9.2 段落と空行

- 一段落は1～3文を基本とする
- 一段落は60～160文字程度を目安にする
- 話題が変わったら空行を入れる
- スマートフォンで6行以上続く段落は分割を検討する
- 一文ごとに必ず改行する必要はない
- 空行を2つ以上連続させない

改行はHTMLの`<br>`を大量に入れて作らない。

Markdownの段落として管理し、画面幅に応じて自然に折り返す。

### 9.3 AIらしい言い回しを減らす

次の表現は原則として書き換える。

- このように
- さらに
- 一方で
- とりわけ
- 非常に重要です
- 多面的に
- 包括的に
- ～と言えるでしょう
- ～ではないでしょうか
- ～することができます
- 今後ますます重要になります
- 重要な役割を果たします
- さまざまな要因が複雑に絡み合っています

必要な接続詞まで削らない。

文章の順番で意味が通る場合だけ削る。

### 9.4 書式の癖

- 「太字のラベル：説明」の箇条書きを連続させない
- 何でも3項目にまとめない
- 全角ダッシュを多用しない
- 絵文字を本文の見出しに使わない
- 太字は一つの段落で1箇所以内を目安にする
- 感嘆符を続けない
- 同じ語尾を3回以上続けない
- 「あなた」を繰り返さない

### 9.5 人の声を残す

AIらしい表現を削るだけでは、内容が無機質になる。

実際の確認方法、院内での説明、川上卓哉の考えを入れる。

ただし、架空の患者、会話、症例は作らない。

## 10. 医学情報と表現上の制限

### 10.1 使用しない表現

- 治療
- 治る
- 完治
- 必ず良くなる
- 絶対に改善する
- 根本解決
- 一回で良くなる
- 再発しない
- 原因を完全に見つける
- 病院では分からない原因が分かる
- 薬や手術は必要ない
- 誰にでも効果がある
- 他院より優れていると断定する表現

医学的な説明に必要な場合の「治療法」「治療選択」などは、引用元の説明として使用可否を個別確認する。

整体院の提供内容は「施術」と表記する。

### 10.2 医学情報の出典

優先順位は次のとおり。

1. 厚生労働省などの公的機関
2. 日本整形外科学会などの医学会
3. 大学病院、公的病院
4. 診療ガイドライン、査読論文
5. 信頼できる医療機関

出典のない断定は書かない。

原因を一つに決めつけない。

### 10.3 受診目安

次の内容を扱う記事には、医療機関への相談を優先する状態を入れる。

- 強いしびれ
- 筋力低下
- 排尿や排便の異常
- 急な症状の悪化
- 外傷後の強い痛み
- 発熱、体重減少、全身状態の変化
- 夜間に強くなる痛み

病名を診断するような書き方はしない。

## 11. 内部リンク仕様

### 11.1 1記事あたりの基準

新規記事には次の内部リンクを設置する。

- 対応する症状ページ：1件
- 関連コラム：2～3件
- 施術者プロフィール：1件
- 必要に応じてアクセスまたは予約案内：1件

リンク総数を増やすためだけの設置は禁止する。

### 11.2 本文内リンク

リンクは、読者が次に知りたくなる場所へ置く。

「こちら」「詳しくはこちら」だけをリンク文字にしない。

良い例：

> [坐骨神経痛で医療機関への相談を優先したい状態](/blog/posts/sciatica-medical-check/index.html)

リンク先の内容と、リンク文字を一致させる。

### 11.3 新規記事への入口

新規記事を公開するときは、既存記事2件以上からリンクする。

新しい記事から既存記事へリンクするだけでは不十分とする。

### 11.4 関連記事の表示

記事末の関連記事は2～3件とする。

本文内ではカードを使わず、通常のテキストリンクにする。

記事末も大きなカードを並べない。

次の形式を基本とする。

```text
関連記事

・長く座るとお尻や足がつらいときに確認したいこと
・坐骨神経痛で運動を始める前に知っておきたいこと
・医療機関への相談を優先したい症状
```

### 11.5 管理項目

原稿のfrontmatterへ次を追加する。

```yaml
parentSymptom: /symptoms/sciatica.html
relatedSlugs: sciatica-exercise,sciatica-medical-check
searchIntent: 長く座ると坐骨神経痛がつらい理由と対処を知りたい
```

生成時にリンク切れを検査する。

関連先が存在しない場合は生成を失敗させる。

## 12. デザイン方針

### 12.1 共通方針

コラム詳細は「カードを見る画面」ではなく「文章を読む画面」とする。

背景は白を基本とする。

枠、影、角丸を重ねない。

記事本文で背景色を使うのは次に限る。

- 医療機関への相談を優先する状態
- 自宅で行う際の注意
- 川上卓哉からの補足

これらもカードのような影は付けない。

左の線、薄い背景、見出しで区別する。

### 12.2 ブレークポイント

| 区分 | 画面幅 |
|---|---:|
| スマートフォン | 0～767px |
| タブレット | 768～1023px |
| PC | 1024px以上 |

## 13. スマートフォン仕様

スマートフォンを優先して設計する。

### 13.1 レイアウト

- 1カラム
- 左右余白：20px
- 360px幅でも横スクロールを出さない
- H1を画像へ重ねない
- パンくずは1行または横スクロール
- 目次は開閉式
- サイドバーは表示しない
- 本文画像は幅100％
- 画像下に説明文を表示する
- 関連記事は縦のテキスト一覧
- 大きな追従CTAを追加しない

### 13.2 文字

| 要素 | 目安 |
|---|---:|
| 本文 | 17px |
| 本文行間 | 1.9 |
| H1 | 27～30px |
| H1行間 | 1.4～1.5 |
| H2 | 22～24px |
| H3 | 19～20px |
| 注釈・画像説明 | 13～14px |

本文を16px未満にしない。

### 13.3 余白

- 段落下：1.2～1.5em
- H2上：2.5～3em
- H2下：1～1.3em
- H3上：2em
- 画像上下：1.8～2.2em
- リンクのタップ領域：高さ44pxを目安

文章が詰まって見えないことを優先する。

### 13.4 表

表は必要な場合だけ使用する。

スマートフォンで収まらない表は横スクロール対応とする。

表の内容をカードへ変換しない。

日本語本文は1行35～42文字程度を目安とする。

### 14.3 目次

H2を基本に表示する。

H3をすべて表示して長くしすぎない。

現在位置を控えめな色で示す。

予約ボタンを目次へ混在させない。

## 15. コラム一覧仕様

カード型は一覧ページのみ使用してよい。

ただし、情報を詰め込みすぎない。

### スマートフォン

- 1列
- 画像、カテゴリー、タイトル、説明、日付
- カード間に十分な余白
- 影は使わないか、ごく薄くする
- タイトルは最大3行

### PC

- 2～3列
- 画像比率を統一
- カード全体をクリック可能にする
- 同じ高さにするため本文を不自然に切らない

一覧上部にはカテゴリーと症状による絞り込みを用意する。

タグを大量に並べない。

## 16. 画像仕様

### 16.1 使用枚数

1記事2～4枚を基本とする。

- メイン画像：1枚
- 症状や身体の説明：0～1枚
- 姿勢、動作、運動：0～1枚
- 院内、施術者、アクセス：必要な場合だけ1枚

画像枚数をそろえるために、意味のない素材画像を追加しない。

### 16.2 元画像の受け渡し

提供された画像フォルダ内の素材は、サイト掲載と加工が許可されたものとして扱う。

実写とイラストの両方を使用する。

推奨する受け渡し構成：

```text
article-images/
└─ {slug}/
   ├─ hero.jpg
   ├─ symptom-area.png
   ├─ movement-check.jpg
   └─ self-care.jpg
```

受け取り後、次へ配置する。

```text
content/assets/blog/{slug}/
```

生成したWeb用画像は次へ出力する。

```text
image/blog/{slug}/
```

### 16.3 元画像サイズ

| 用途 | 推奨サイズ |
|---|---:|
| メイン画像 | 2400×1350px以上、16:9 |
| 本文写真 | 1800×1200px以上、3:2 |
| 説明図 | 1600×1200px以上、4:3 |
| 正方形素材 | 1600×1600px以上 |

重要な人物や部位を画像の端へ置かない。

画像内に長い文章を入れない。

### 16.4 ファイル名

英小文字、数字、ハイフンを使用する。

```text
{slug}-hero.jpg
{slug}-symptom-area.png
{slug}-movement-check.jpg
{slug}-self-care.jpg
```

使用しない例：

```text
画像1.jpg
完成版（最新）.png
IMG_1234.jpg
坐骨神経痛.jpg
```

### 16.5 Web用出力

写真はWebPを基本とする。

透過が必要な図はWebPまたはPNGとする。

長辺または表示幅に合わせ、次のサイズを生成する。

- 480px
- 768px
- 1200px

`srcset`と`sizes`で、画面幅に合う画像を配信する。

ファーストビュー画像以外は遅延読み込みする。

`width`と`height`を指定し、読み込み中の画面ずれを防ぐ。

### 16.6 画像説明

すべての画像に代替テキストを付ける。

装飾目的の画像は空の代替テキストとする。

図や写真の下には、必要に応じて短い説明を付ける。

画像内で説明を完結させない。

### 16.7 画像の内容

- 痛みを過度に強調しない
- 原因を一つに断定する図を使わない
- 医学的な図は川上卓哉が確認する
- 人物が写る場合は掲載許可を確認する
- AI生成画像を実際の施術風景として扱わない
- AI生成の説明図は医学的内容を確認する

## 17. Markdownと生成機能

### 17.1 原稿の管理

新規原稿と記事改修は`content/source/*.md`だけを編集する。

生成後の`blog/`、`blog.html`、`blog-detail.html`は直接編集しない。

### 17.2 frontmatter

既存項目に加え、次を管理できるようにする。

```yaml
---
title: 記事タイトル
slug: article-slug
date: YYYY-MM-DD
updated: YYYY-MM-DD
description: 検索結果に表示する説明
category: 坐骨神経痛
region: 柏市
tags: 坐骨神経痛,足のしびれ
symptoms: 坐骨神経痛,腰痛
heroImage: /image/blog/article-slug/article-slug-hero-1200.webp
heroAlt: 椅子に座りながらお尻から足の違和感を気にする様子
author: 川上卓哉
reviewer: 川上卓哉
reviewedDate: YYYY-MM-DD
parentSymptom: /symptoms/sciatica.html
relatedSlugs: article-a,article-b
searchIntent: 長く座ると坐骨神経痛がつらい理由を知りたい
layout: readable-v3
draft: true
---
```

`updated`は内容を実際に変更した場合だけ設定する。

### 17.3 本文画像記法

Markdown画像を正式に処理する。

```markdown
![椅子から立ち上がるときの足の位置](/image/blog/article-slug/article-slug-movement-check-1200.webp "立ち上がりでは足の位置も確認します")
```

生成結果：

```html
<figure>
  <picture>...</picture>
  <figcaption>立ち上がりでは足の位置も確認します</figcaption>
</figure>
```

画像を通常の段落として出力しない。

### 17.4 共通情報

次の情報を生成プログラムへ直接重複記載しない。

- 初回料金
- 初回時間
- 施術歴
- 施術実績
- 営業時間
- 定休日
- 住所
- プロフィールURL

共通設定またはTOPページの共通データを参照する。

### 17.5 生成コマンド

全記事：

```bash
npm run generate:blog
```

1記事：

```bash
npm run generate:blog:source -- --source content/source/YYYY-MM-slug.md
```

## 18. SEO仕様

### 18.1 タイトル

- 検索した人の疑問が分かる
- 地域名は必要な記事だけに入れる
- 症状名を不自然に繰り返さない
- 煽る表現を使わない
- 目安は28～36文字程度

### 18.2 メタディスクリプション

- 110～140文字程度
- 記事で分かることを書く
- 効果を保証しない
- 同じ文章を使い回さない

### 18.3 構造化データ

`BlogPosting`または`Article`を使用する。

次を含める。

- `headline`
- `description`
- `image`
- `datePublished`
- `dateModified`
- `author`
- `reviewedBy`
- `mainEntityOfPage`
- `publisher`
- `citation`

著者は人物として川上卓哉を設定し、`url`をプロフィールページへ向ける。

FAQが本文に存在する場合だけFAQデータを生成する。

### 18.4 canonicalとサイトマップ

- 各記事に自己参照canonicalを設定する
- 公開記事だけサイトマップへ追加する
- 実質的な変更時だけ`lastmod`を更新する
- `draft: true`は公開一覧とサイトマップから除外する

## 19. 計測仕様

### 19.1 現状

Google Search Consoleは運用中。

GA4もサイトへ導入済みで、測定IDは設定されている。

現在はLINE、電話、予約、関連記事などのクリック計測がある。

コラムの読了状況は追加計測する。

### 19.2 追加イベント

| イベント名 | 発火条件 |
|---|---|
| `article_view` | コラム詳細を表示 |
| `article_scroll_50` | 本文の50％に到達 |
| `article_scroll_90` | 本文の90％に到達 |
| `article_toc_click` | 目次を選択 |
| `article_internal_link_click` | 本文内の内部リンクを選択 |
| `article_related_click` | 関連記事を選択 |
| `article_staff_profile_click` | プロフィールを選択 |
| `article_line_click` | 記事内LINE案内を選択 |

同じイベントを一つの閲覧で何度も送信しない。

イベントには次を含める。

- 記事slug
- カテゴリー
- リンク先slug
- リンク位置
- PCまたはスマートフォン

### 19.3 Search Consoleの確認

毎月、次を確認する。

- 表示回数
- クリック数
- クリック率
- 平均掲載順位
- 検索クエリ
- ページ別の変化

28日と前の28日を比較する。

3か月と前の3か月も比較する。

順位だけで成否を判断しない。

### 19.4 改修判断

| 状況 | 対応 |
|---|---|
| 表示回数が増え、クリック率が低い | タイトルと説明を見直す |
| 11～30位で表示が増えている | 内容と内部リンクを追加する |
| 読了率が低い | 導入、段落、画像位置を見直す |
| 関連記事が押されない | リンク文と配置を見直す |
| 内容が重複する | 統合または検索意図を分ける |

## 20. アクセシビリティ

- 本文と背景のコントラストを確保する
- 色だけで注意を表現しない
- リンクは色と下線で判別できるようにする
- キーボードで目次とリンクを操作できるようにする
- フォーカス表示を消さない
- 画像に代替テキストを付ける
- 見出し順をH1、H2、H3の順にする
- タップ領域は44pxを目安にする
- 200％拡大でも横スクロールを出さない
- 動きを付ける場合は控えめにする

基準はWCAG 2.2を参照する。

## 21. 表示速度

- ファーストビュー画像を優先読み込みする
- 本文画像は遅延読み込みする
- 画像の幅と高さを指定する
- 未使用CSSとJavaScriptを増やさない
- カード用の重いアニメーションを追加しない
- Webフォントを増やしすぎない
- スマートフォンの低速回線で確認する

目標：

- LCP：2.5秒以内を目安
- CLS：0.1以下を目安
- INP：200ms以内を目安

## 22. 既存44記事の移行

### 22.1 移行順

1. 共通デザインと生成機能を完成させる
2. `readable-v2`の5記事で新仕様を検証する
3. 文字数が少ない8記事を改修する
4. Search Consoleで表示回数が多い記事を改修する
5. 腰、坐骨神経痛、膝の記事をクラスター単位で改修する
6. 残りを毎週3～5記事ずつ移行する

### 22.2 URL

原則として既存URLを変更しない。

変更が必要な場合は、旧URLから301リダイレクトする。

タイトル変更だけでURLを変更しない。

### 22.3 改修時の確認

- 文字数の水増しがない
- 画像が内容と合っている
- 関連症状ページへリンクしている
- 関連コラムが2件以上ある
- 既存記事からの入口がある
- 医学情報に出典がある
- 古い料金や施術歴が残っていない
- 禁止表現がない
- スマートフォンで読みにくい段落がない

## 23. 公開手順

1. Search Consoleと既存記事からテーマを選ぶ
2. 検索意図と重複記事を確認する
3. 一次情報を調べる
4. 川上さんメモを確認する
5. 構成案を作る
6. 1,500～3,000文字を目安に執筆する
7. 画像を選定する
8. 内部リンクを設置する
9. AIらしい表現と読点を見直す
10. 医学情報、禁止表現、口コミの扱いを確認する
11. `draft: true`で生成する
12. PCとスマートフォンで表示確認する
13. 川上卓哉が最終確認する
14. `draft: false`へ変更する
15. 生成、テスト、公開を行う
16. 公開後にSearch Consoleで登録状況を確認する

## 24. テストと受け入れ条件

### 24.1 自動確認

- Markdown画像が`figure`として生成される
- 画像の代替テキストが空でない
- `srcset`が生成される
- 内部リンク切れがない
- `relatedSlugs`の対象が存在する
- H1が1つだけ存在する
- 見出し階層が正しい
- canonicalが正しい
- 構造化データがJSONとして有効
- 下書きが公開一覧へ出ない
- 料金と施術歴が共通データから出力される

### 24.2 スマートフォン確認

幅360px、390px、430pxで確認する。

- 横スクロールがない
- 本文が17px以上
- 目次を開閉できる
- H1が画像と重ならない
- 表が画面を壊さない
- 画像がぼやけない
- タップしにくいリンクがない
- カードが連続していない
- 段落が長く詰まって見えない

### 24.3 PC確認

幅1280px、1440pxで確認する。

- 本文幅が720pxを大きく超えない
- 目次が本文を圧迫しない
- 画像が引き伸ばされない
- 行が長すぎない
- 見出し前後の余白がある
- 関連記事が大きなカードで画面を占有しない

### 24.4 原稿確認

- 一文に読点が多すぎない
- 同じ語尾が続いていない
- 不要な接続詞がない
- 一段落がスマートフォンで6行以上続いていない
- AI特有の定型表現が残っていない
- 架空の体験談がない
- 医療機関を否定していない
- 結果を保証していない
- 川上卓哉の発言が本人確認済み
