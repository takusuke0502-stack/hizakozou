# ポスティング分析ダッシュボード運用メモ

## URLと公開範囲

- 画面URL: `/posting-analysis/`
- 公開サイトのナビゲーションやサイトマップには追加しない
- 画面には `noindex,nofollow,noarchive` を設定済み
- アクセス認証はないため、患者名・電話番号などの個人情報は入力しない

## できること

- 柏市318町丁目を、年代構成・世帯数・配布余地・登録済み実績で比較
- 地域名、優先度、年代、世帯数、距離、配布状況、問い合わせ、チラシ別のAND絞り込み
- S/A/B/Cの優先度と「次に配る候補」最大5件の表示
- 配布日、配布枚数、チラシ、ルートID、GPSセッションIDの記録
- 問い合わせ、来院、継続、売上の地域・チラシ別集計
- JSONバックアップの書き出しと復元

## 保存場所

運用データはサーバーへ送信せず、利用中のブラウザの `localStorage` に保存します。

- `hizakozou.posting.records.v1`: 配布実績
- `hizakozou.posting.inquiries.v1`: 問い合わせ実績
- `hizakozou.posting.flyers.v1`: チラシデザイン
- `hizakozou.posting.distances.v1`: 地域別距離

端末やブラウザを変更しても自動同期されません。定期的に画面上部の「バックアップ」からJSONを保存し、別端末では「復元」を使用します。

## スコア

設定ファイルは `data/posting/scoring_config.json` です。

- 人口統計・膝痛ターゲット: 40%
- 距離: 25%
- 反響実績: 20%
- 継続・売上: 10%
- 配布余地: 5%

距離や実績がない項目は0点にせず、利用可能な項目のウェイトだけで100点換算します。反響実績は配布1,000枚未満の場合、配布枚数に応じて寄与を弱めます。

初期の旧デザインには、地域を特定できない既知の問い合わせ2件を保持しています。この2件は全体件数には含めますが、地域別反響率や地域ランキングには加算しません。

## 柏市データの更新

1. 柏市公式データを確認する
   - 年代構成: 4月・10月更新
   - 人口・世帯数: 毎月更新
2. 同じデータ契約で `data/posting/region_master.json` を更新する
3. 地域名や区画に変更があれば `data/posting/region_aliases.csv` も更新する
4. `metadata.record_count`、基準日、町丁目コードの重複がないことを確認する
5. `npm test` を実行してから公開する

距離は推測値を入れず、確認できた値だけを地域詳細から登録します。柏市公式人口マスターと境界データの区画が一致すると確認できるまではnullableのまま運用できます。
